## 來源優先次序

1. **先用馬會官方資料**：排位表、出賽馬匹及騎練資料、往績、賽事評語、分段時間、試閘、操練、配備、獸醫／退出公告、場地狀況、賠率、正式賽果。
2. **再用可核實一手來源**：練馬師或騎師訪問、馬房正式公布、賽事直播及走位影片。記低發布時間、原句同連結，唔好用轉述冒充原話。
3. **最後先用二手來源**：報章、馬評、數據網站只作補充或找線索；重要事實盡量搵官方或第二個獨立來源核實。馬評心水屬意見，唔係馬房意圖證據。
4. **唔好繞過登入、付費牆、Captcha 或網站限制**。頁面失效就記錄缺口，請用戶提供 PDF／截圖；唔好憑記憶補數。

## 自動工作流程

1. 確認日期、馬場、場次、開跑時間同時區；用戶冇指明而又有歧義就先問，唔好自動揀一場當答案。
2. 搜官方排位表，核對場次、馬號、馬名、騎師、練馬師、檔位、負磅、評分、配備同退出名單。
3. 逐匹抽取同場同程、近期往績、班次／路程轉變、休息日數、場地適性、段速、試閘／操練及騎練組合。保留樣本數，唔好齋抄百分比。
4. 搜同場可能改變判斷嘅新聞：轉倉、傷患、見習減磅、配備、報名部署、騎師選擇、直接訪問。
5. 臨場任務先再取場地、退出、賠率同時間戳。T-1、T-60、T-10、T-3 只係建議快照；用戶冇要求定時或持續監察，就唔好自行建立排程。
6. 將每個時點寫成獨立 race-card JSON，執行 `import-card`。相同馬號嘅臨場更新要新增快照，唔好覆寫舊檔。
7. 賽後以官方賽果寫 race-result JSON，執行 `import-result`。修正賽果都要新增結果快照。

## 必收欄位

| 層級 | 必要資料 | 可選但有用 |
|---|---|---|
| 賽事 | race_id、日期、馬場、場次、開跑時間、路程、資料截止時間、來源 | 班次、場地、跑道、declared_starters、位置名額、獎金 |
| 馬匹 | 馬號、馬名、退出狀態 | 馬匹 ID、年齡、評分、檔位、負磅、騎練 |
| 市場 | 同一時點全場獨贏賠率先可計完整去水基準 | 位置賠率、歷史賠率序列 |
| 特徵 | 只放開跑前已存在嘅數值 | 同程率、近績、速度分、休息、騎練統計 |
| 意圖 | 每項訊號附 signal、方向、強度、置信度、source_id、原文摘錄 | 相反證據、觀察限制 |

## 時間與證據規則

- 所有 `captured_at`、`data_cutoff`、`off_time` 用带時區 ISO-8601；香港用 `+08:00`。
- `data_cutoff` 唔可以遲過開跑時間。即場快照嘅 `captured_at` 亦唔可以遲過開跑時間。
- 歷史重建必須設 `collection_mode: historical`；只可話係回測，唔可以話係當日真實預測。
- 賠率要全場同一快照。只有部分馬有賠率時，程式會退回均勻市場基準並發警告；唔好自行補飛。
- 原始網頁／PDF 可存 `racing-data/sources/<race_id>/`；normalized JSON、來源登記同內容雜湊共同構成審計鏈。
- 輸出引用用當輪工具真正讀過嘅來源；冇讀過唔好引。
- 意圖證據要保留逐字 `quote`，並把讀到嘅原文段落放入 `source.excerpt`；程式會核對兩者。寫唔出逐字原文，就唔好當證據。
- `place_slots` 唔填會按 `declared_starters` 自動推導（本地賽 7 匹或以上 3 位、4-6 匹 2 位；少於 4 匹只係 1 位模型近似，唔代表有正式 Place pool）。

## 缺口處理

- 將缺口分成「核心欄位缺失」「部分特徵缺失」「無法核實意圖」三類，喺報告列明。
- 核心馬號／場次／開跑時間有矛盾就停低核實；唔好硬出概率。
- 缺某項特徵就用模型訓練時嘅中位數填補，並報告 coverage；唔好將缺失當 0 或當負面證據。
- 冇意圖證據就輸出「證據不足」，分數 50、低置信；唔好靠馬名、名氣或賽果幻想動機。

## 賠率攝取（HKJC）

### 官方頁面

| 用途 | URL 模式 |
|---|---|
| 獨贏／位置賠率（每分鐘更新） | `https://bet.hkjc.com/ch/racing/wp/YYYY-MM-DD/ST/1` |
| 賽日卡（含即時賠率） | `https://bet.hkjc.com/ch/racing/home/?lang=zh&venue=st&date=YYYY-MM-DD&race=1` |
| 越洋轉播（S1–S5） | 同一 `wp` 路徑，venue 用 `S1`（例：`/racing/wp/2026-10-24/S1/3`） |
| 賽果 | `https://racing.hkjc.com/zh-hk/local/information/localresults?racedate=YYYY/MM/DD&Racecourse=ST&RaceNo=N` |

### 建議流程

1. **T-60／T-10／T-3 各抓一次**，寫成獨立 JSON（唔好覆寫舊檔）：

```json
{
  "race_id": "2026-10-24-S1-3",
  "captured_at": "2026-10-24T10:30:00+08:00",
  "source": {"source_id": "HKJC-WP", "title": "HKJC 獨贏賠率", "url": "https://bet.hkjc.com/ch/racing/wp/2026-10-24/S1/3"},
  "odds": [{"horse_no": 2, "win_odds": 2.4}, {"horse_no": 11, "win_odds": 4.8}]
}
```

2. `import-odds --db ... --file odds.json` → 新增 card snapshot，保留 `odds_snapshot.minutes_to_off`。
3. `diagnose-card --db ... --race-id ...` → 確認 `market_completeness == 1.0` 才預測。
4. 有馬冇賠率就當缺口，**唔好自行估算或補飛**；寧願等下一次快照。

### 紀律

- 賠率係 pari-mutuel，落注會改變派彩；同一時點全場齊全才有完整去水基準。
- `captured_at` 必須早於 `off_time`；`import-odds` 會拒絕開跑後補數，亦會拒絕已匯入賽果的場次。
- 尊重網站限制：每次請求之間至少隔一分鐘、加 cache、唔好繞過登入／付費牆。
- 只保存你真正讀取過的原始頁面；引用時連時間戳一齊記。
