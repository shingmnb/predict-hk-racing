# 情報優先改進路線圖

> 呢份路線圖保留外部實戰系統交叉評審嘅有用方向，但以情報質素為核心重新排序。外部結果、引用數同文獻摘要未喺本 repo 獨立重現或核實，唔好當成已驗證優勢。編號只係規劃 ID，唔對應 GitHub PR。

## 核心原則

1. 先加深一場嘅證據鏈，再擴大場數；唔好用下載量冒充有效樣本。
2. 核心輸出係事實、支持、反證、未知及部署支持度；冇已驗證模型就唔出勝率。
3. 原始賠率只作可選市場消息，保存時間與數值，唔轉成概率、唔入模型特徵。
4. 新訊號先登記候選假設，再用時間外消融驗證；陰性結果都要保存。

## P0｜逐匹上仗／今仗情報對比

**缺口**：只記今仗配備或騎師，容易將普通變更誤讀成部署。

**做法**：逐匹保存上仗與今仗原始行，對比配備、騎師、班次、路程、負磅、檔位、休息、試閘、操練及健康；騎師變更要再查同倉其他馬、可選騎師、體重、合約、檔期與直接訪問。

**每條 claim 必備**：

- 原文 `quote`、完整 `source.excerpt`、URL、發布與擷取時間；
- 觀察事實與推論分開；
- 至少一項主動尋找嘅反證；
- 未知、替代解釋同撤回條件；
- 冇逐字原文就標「證據不足」，唔入評分。

**驗收**：核心欄位 100% 對原件；抽核引文與標籤；獨立盲審報一致率、分歧與裁決。騎師不同唔可以直接寫成「主動選鞍」。

## P0｜可重現嘅賽前情報封存

**缺口**：事後睇賽果再寫理由，會令情報分析失真。

**做法**：第一次接觸賠率前，封存基本面短名單、支持／反證、替代劇本、`fundamental_created_at` 與 `market_blind`；之後執行 `import-card` 同 `analyze`。臨場變更新增快照與 run，唔改舊版。

**驗收**：第三方可由原件、manifest 與程式版本重現相同輸出；`analyze` 冇概率欄；開跑後補做嘅資料只屬 historical，唔混入 forward KPI。

## P1｜官方資料 fetch 層

**缺口**：而家 race-card JSON 主要靠操作者整理，資料累積同核對成本高。

**候選工具**：`scripts/fetch_card.py`，分開排位、原始市場快照與結果三個流程，全部輸出符合現有 schema。

- 排位：HKJC 官方排位 PDF／HTML → 馬號、馬名、騎練、檔位、負磅、評分、配備、退出與來源。
- 市場：合法公開頁面 → 同一時點原始 WIN／PLA、頁面時間與擷取時間；只作 `market_move` 觀察。
- 結果：官方賽果 → 名次、狀態、派彩與賽後來源；唔入賽前特徵。

**驗收**：真實賽日樣本通過 schema、`data_cutoff <= off_time`、退出／後備處理、哈希與未來資料測試。網站限制、Captcha 或登入牆要停止並記錄，唔好繞過。

## P1｜歷史 bridge 與 coverage ledger

**缺口**：模型驗證需要樣本，但歷史資料未必能證明當時已存在。

**做法**：將合法保存嘅歷史排位、情報、原始市場快照與賽果分批轉成現有 JSON，全部標 `collection_mode: historical`。逐場記 `eligible_for`、`excluded_reason`、特徵覆蓋與證據缺口。

**驗收**：原件、內容雜湊、實際擷取時間及可用性證明齊全；下載 200+ 場唔等於 200+ 有效樣本；只有賽果或最終賠率嘅場次唔得補寫成賽前情報。

## P1｜情報 claim 登記與賽後核查

每項重要消息登記：訊號類別、適用窗口、原文、推論、反證、未知、撤回條件與當時版本。賽後只核對可觀察部分：

- 事實與提取係咪正確；
- 有冇新官方資料支持替代解釋；
- 事先寫低嘅形勢劇本有冇出現；
- 邊啲係不可預測事件。

贏咗唔等於「證明去馬」，輸咗亦唔等於「證明保留」。真正意圖通常冇外部 ground truth，唔好製造虛假標籤。

## P2｜傳媒共識（獨立觀察，唔係意圖）

`tipster_consensus` 可以作候選市場情緒特徵，但唔入部署支持度。要保存每位評家、原始排名、時間與缺失，避免將轉載當獨立票數。

只有歷史樣本足夠時，先同能力特徵做消融；未通過時間外驗證前，只可作報告觀察，唔好當固定權重。

## P2｜可選概率模型與情報消融

情報分析本身唔依賴模型。用戶明確需要概率、有效樣本達標時，先比較：

1. 能力特徵模型；
2. 能力＋`intent_centered` 模型；
3. 同一窗口移除情報 block 嘅 ablation；
4. 均勻無資訊內部基準與現任 champion。

只有 log loss、Brier、bootstrap、多重比較、required ablation、校準與 champion 門檻全部通過，先 promoted 並供 `predict` 使用。否則保留 `analyze`，唔好用均勻值或原始賠率補概率。

## 暫不擴張

- 海外賽事與更多彩池：先完成本地賽事證據鏈。
- 複雜 ensemble／Transformer：樣本與情報標籤未支持前唔增加複雜度。
- 自動下注：唔屬情報核心；任何價值研究另須完整事前注項、官方派彩、成本與回撤驗收。
- 固定「消息加幾多個百分點」規則：未經時間外驗證一律唔採用。
